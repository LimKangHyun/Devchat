# 일정(캘린더) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DevChat 안의 개인 일정(반복, 참여자, 알림)과 애플 캘린더 구독 주소, 채팅 메시지의 날짜를 눌러 일정 만들기를 만든다.

**Architecture:**
- 백엔드에 새 도메인 `domain/schedule`을 만든다.
  - 일정 1건(반복 규칙 포함), 참여자, 알림 오프셋, 뺀 날짜를 저장한다.
  - 반복 회차는 저장하지 않고 필요한 구간만 순수 함수로 계산한다.
- 알림은 1분마다 도는 스케줄러가 맡는다. 유니크 키가 있는 발송 기록에 먼저 넣는 데 성공한 서버만 보내서 중복을 막는다.
- 애플 캘린더는 사람별 비밀 토큰 주소로 iCalendar(.ics)를 내려준다.
- 프론트는 왼쪽 목록의 "일정" 탭과 `/calendar` 페이지, 그리고 채팅 메시지 속 날짜 인식으로 이루어진다.

**Tech Stack:** Spring Boot 3 / Java 21, JPA + Flyway(MySQL), StringRedisTemplate, 기존 알림(웹소켓 + 웹 푸시); React(CRA), lucide-react, Jest. 새 라이브러리는 추가하지 않는다.

**Spec:** `docs/superpowers/specs/2026-10-28-calendar-and-devices-design.md` (1부)

## Global Constraints

- 시간대는 `Asia/Seoul` 고정이다. 서버의 `LocalDateTime`/`LocalDate`는 모두 한국 시간이다.
- 권한
  - 고치기, 지우기, 이번만 빼기는 만든 사람만 할 수 있다.
  - 참여자는 보기와 나가기만 할 수 있다.
  - 볼 수 있는 사람은 만든 사람과 참여자뿐이다. 그 외에는 404로 답한다.
- 참여자로 넣을 수 있는 사람: 내 친구, 또는 나와 같은 활성 채팅방에 있는 사람. 나 자신은 넣지 않는다. 서버에서 검사하고, 어기면 400으로 답한다.
- 참여자는 수락 없이 바로 추가된다.
- 반복 규칙
  - 종류: NONE, DAILY, WEEKLY(요일 여러 개), MONTHLY(같은 날짜, 없는 달은 건너뜀), YEARLY(2월 29일은 윤년만)
  - 끝: 없음, 날짜까지(그날 포함), N번. N번은 뺀 날짜를 빼기 전 기준으로 센다 (RFC 5545와 같다).
- 반복 일정 지우기는 "이번만 빼기"와 "전체 지우기"뿐이다. 고치기는 항상 전체에 적용된다.
- 알림
  - 정수 `minutesBefore` 하나로 저장하고, 기준 시각에서 그만큼 앞선 때에 보낸다.
    - 시간이 있는 일정의 기준 시각은 시작 시각이다.
    - 하루 종일 일정의 기준 시각은 그날 00:00이다. 그래서 "하루 전 오전 9시"는 900, "당일 오전 9시"는 -540이다.
  - 기본값: 시간이 있는 일정은 30, 하루 종일 일정은 900이다.
  - 일정 하나에 알림은 최대 5개, 값 범위는 -1439 ~ 10080(7일)이다.
- 알림은 만든 사람과 참여자 모두에게 간다.
  - 보낼 시각에서 10분 넘게 지난 알림은 보내지 않는다.
  - 같은 (일정, 회차 시작, minutesBefore)는 한 번만 보낸다. 블루/그린 배포로 서버 두 대가 같이 돌아도 마찬가지다.
- 일정 알림 4종 (`NotificationType`에 추가)

  | 타입 | 받는 사람 | 문구 |
  |---|---|---|
  | `SCHEDULE_ADDED` | 새로 추가된 참여자 | `"{닉네임}님이 '{제목}' 일정에 추가했어요"` |
  | `SCHEDULE_CHANGED` | 참여자 (시작·끝·하루 종일·반복이 바뀌었거나 이번만 빼기를 했을 때. 제목·장소·메모만 바뀌면 보내지 않는다) | `"'{제목}' 일정이 바뀌었어요"` |
  | `SCHEDULE_CANCELED` | 참여자 (일정을 지웠거나 그 참여자를 뺐을 때) | `"'{제목}' 일정이 취소됐어요"` |
  | `SCHEDULE_REMINDER` | 만든 사람 + 참여자 | `"'{제목}' {M월 d일 (E) a h:mm}"` (하루 종일이면 `"'{제목}' {M월 d일 (E)} 하루 종일"`) |

  - 만든 사람 본인에게는 ADDED/CHANGED/CANCELED를 보내지 않는다.
- 구독 주소
  - 형식: `{app.base-url}/api/calendar/feed/{token}.ics`. nginx가 `/api/`를 떼고 백엔드로 넘기므로 백엔드 경로는 `/calendar/feed/{token}.ics`이다.
  - 로그인 없이 열린다. 토큰은 32바이트 랜덤을 base64url로 만든다.
  - DB에는 조회용 SHA-256 해시와, 다시 보여 주기 위한 `CryptUtils` 암호문을 함께 저장한다.
  - "새로 만들기"를 하면 예전 토큰은 바로 무효가 된다.
  - 토큰 하나당 시간당 120회로 제한하고, 넘으면 429로 답한다.
  - 피드 내용: 내가 만든 일정 + 내가 참여자인 일정. 참여자는 닉네임만 넣는다. 달력 이름은 `DevChat`이다.
- 알림은 애플 캘린더에 의존하지 않는다. 피드에 `VALARM`을 넣지 않는다.
- 채팅 날짜 인식
  - 프론트 순수 함수로 만든다.
  - 기준 날짜는 메시지를 보낸 시각(KST)이다.
  - 코드 블록, URL, 멘션 안의 숫자는 날짜로 보지 않는다.
  - 시간이 없으면 하루 종일 일정이고, 시간만 있으면 길이 1시간이다.
- 채팅방에서 일정을 만들 때도 참여자 칸은 비워 둔다.
- 화면
  - 왼쪽 목록에 "일정" 탭을 두고, 가운데는 월/주 보기다.
  - 휴대폰은 작은 월 달력 아래에 그날 일정 목록을 보여 준다.
  - 확인 창은 앱 모달로 띄운다 (`window.confirm`, `alert`는 쓰지 않는다).
- 하지 않는 것: 참석/거절, 사람별 알림, 이번만 시간 옮기기, 이후 모두 바꾸기, 애플 → DevChat 동기화, 구글 전용 연동, 방 공용 달력, 애매한 날짜("이번 달 말쯤")
- Flyway 새 파일은 `V16__create_schedule.sql`이다 (V15는 로그인 세션). 로컬은 `docker exec -i mysql mysql -uroot -proot_pw devchat < 파일`로 적용한다.
- 테스트 서버 포트는 백엔드 8098, 프론트 3006이다. 8080과 3000은 건드리지 않는다.
- 커밋 메시지에 Claude 공동 작성자나 생성 문구를 넣지 않는다. 커밋할 때는 자기 파일만 경로를 적어 스테이징한다.

## Review Focus

- **31일 매달 반복과 2월 29일 매년 반복:** 없는 달·해는 건너뛰어야 한다. 날짜를 당겨서 30일이나 28일에 넣으면 안 된다. → Task 2 `monthly31_skipsShortMonths`, `yearlyLeapDay_onlyLeapYears`
- **하루 종일 일정의 "당일 9시" 알림:** 기준이 그날 00:00이라 보낼 시각이 시작보다 뒤다. 그래도 보내야 한다. → Task 5 `allDaySameDayReminder_firesAfterStart`
- **서버가 잠깐 멈춘 경우:** 5분 동안 멈췄다 살아나면 그 사이 알림을 보낸다. 15분 지난 알림은 보내지 않는다. → Task 5 `catchUp_withinTenMinutes_sends`, `staleOverTenMinutes_skipped`
- **로그인 없이 피드 요청이 들어올 때:** `JwtAuthenticationFilter`가 쿠키가 없다고 401로 막으면 애플 캘린더가 영영 못 가져간다. → Task 6 `feed_withoutCookie_returnsCalendar` (MockMvc, 필터 포함)
- **ICS 줄 바꿈과 특수문자:** 제목의 쉼표, 세미콜론, 줄바꿈, 75바이트가 넘는 한글 줄을 iCalendar 규칙대로 처리해야 한다. 안 그러면 애플이 일정을 버린다. → Task 6 `escapesAndFoldsLongKoreanLines`

### Task 2: 반복 회차 계산

**Files:** Create `app/RecurrenceExpander.java` · Test `src/test/java/project/api/domain/schedule/app/RecurrenceExpanderTest.java`

**Interfaces:**
- Consumes: Task 1 `Schedule` getters (`getStartAt`, `getEndAt`, `getRepeatFrequency`, `getRepeatDays`, `getRepeatUntil`, `getRepeatCount`, `getExclusions`)
- Produces:
  - `record Occurrence(LocalDateTime start, LocalDateTime end)` in `app`
  - `static List<Occurrence> RecurrenceExpander.between(Schedule s, LocalDateTime from, LocalDateTime to)`: 회차의 `[start, end]`가 `[from, to)`와 겹치는 것만 시작 순으로 돌려준다. 뺀 날짜는 제외한다. 길이(end - start)는 원본과 같다.
  - `static Optional<Occurrence> RecurrenceExpander.next(Schedule s, LocalDateTime after)`: `start >= after`인 첫 회차. 사이드바 "다가오는 일정"에 쓴다.
  - 계산은 길이 하나만 받는 내부 함수로 짜서 테스트하기 쉽게 한다 (빌더 재량).
- 규칙
  - WEEKLY는 `repeatDays`가 비어 있으면 시작 요일 하나로 본다.
  - 주는 월요일에 시작하고, 시작 주의 시작일 이전 요일은 건너뛴다.
  - 계산 상한은 2,000회차다. 무한 반복을 막기 위한 안전장치다.
